What sticky does

A sticky element behaves like a normal, in-flow element until the scroll position pushes it to a threshold you define. From that moment it behaves like a fixed element, holding its place on screen, until it would leave the boundaries of its parent. Then it scrolls away with that parent.

Unlike position: fixed, a sticky element still takes up its original space in the layout, so nothing jumps when it starts to stick. That makes it a good fit for headers, sidebars, and table headings.

Because it is a hybrid of relative and fixed positioning, it needs a few things to be true at once: an offset, room to move inside its parent, and a clean path up to the scroll container. The following sections cover each one.

The offset is required

Setting position: sticky by itself does nothing visible. The browser needs to know how far from the edge of the scrollport the element should stick, and that comes from top, bottom, left, or right. Without one of them there is no threshold, so the element simply scrolls like any other.

A value of top: 0 pins the element flush against the top edge. A value such as top: 1.5rem leaves a little breathing room, which is what the table of contents here uses.

This failure is silent. There is no console warning and no error, which is why a missing offset is one of the most common reasons sticky seems to be broken.

The containing block

A sticky element can only travel inside its parent. The section heading on this page is a child of its <section>, so it sticks while that section is on screen and then leaves with it as the next heading takes over.

If you want an element to stay visible for the whole page, it has to live in a parent that is as tall as the whole page. That is why the table of contents sits inside the full-height layout container rather than inside a short wrapper.

A parent that is only as tall as the sticky element itself leaves no room to move, so the element appears to do nothing at all.

Overflow breaks it

Sticky measures its offset against the nearest ancestor that is a scroll container. Any overflow value other than visible or clip turns an element into one, even if it never actually scrolls.

Put overflow: hidden on a wrapper and every sticky element inside it starts measuring against that wrapper. The wrapper does not scroll, so the offset is never reached and the element never sticks.

People often add overflow: hidden to round off corners or to trim a decorative shape, which is exactly what the wrapper around this page did. Check the comment in sticky-demo.css to see how it was fixed.

Grid and flex stretch

Grid and flex items stretch to the full height of their row by default. A sticky sidebar that is stretched to the full height of the row has nowhere to travel, because it already fills its parent.

The fix is to stop the stretching with align-self: start (or align-items: flex-start on the container). The sidebar then keeps its natural height and slides within the taller row.

The table of contents on this page relies on exactly that, which you can confirm by turning the alignment rule off in your browser's dev tools.

Debugging checklist

When a sticky element will not stick, walk the list in order. First, confirm it has an offset such as top. Second, check that its parent is taller than the element. Third, look at every ancestor between the element and the viewport for an overflow value that is not visible.

Fourth, if the element is a grid or flex item, check whether it is being stretched. Fifth, remember that height: 100% on a sticky element can make it exactly as tall as its parent, which again leaves no room to move.

Browser dev tools help here: select the sticky element, then walk up the DOM tree and read the computed overflow on each ancestor.
